Gateway Module

The Gateway module handles WebSocket connections to Discord's Gateway for real-time events.

GatewayConnection

Nobelium.Gateway.GatewayConnection — Type
GatewayConnection

Manages a WebSocket connection to the Discord Gateway.

Fields

  • token: Bot token for authentication
  • intents: Gateway intents specifying which events to receive
  • shard: Tuple of (shardid, numshards) for sharding
  • dispatcher: Event dispatcher for handling events
  • ws: WebSocket connection (when connected)
  • session_id: Session ID from Ready event (for resuming)
  • resume_url: Resume URL from Ready event
  • sequence: Last received sequence number
  • heartbeat_interval: Heartbeat interval in milliseconds
  • heartbeat_task: Background task for heartbeating
  • last_heartbeat_ack: Whether last heartbeat was acknowledged
  • connected: Whether currently connected
  • reconnect_attempts: Number of reconnection attempts
source

Event Dispatcher

Nobelium.Gateway.EventDispatcher — Type
EventDispatcher

Manages event handlers for Gateway events. Supports multiple handlers per event type and async execution.

Fields

  • handlers: Dictionary mapping event names to vectors of handler functions
  • lock: ReentrantLock for thread-safe handler registration/removal
  • sequence: Atomic counter tracking the last received sequence number
source
Nobelium.Gateway.on! — Function
on!(dispatcher::EventDispatcher, event::String, handler::Function)

Register an event handler for a specific event type.

Arguments

  • dispatcher: The event dispatcher
  • event: Event name (e.g., "MESSAGECREATE", "GUILDCREATE")
  • handler: Function to call when event is received. Should accept a Dict argument.

Example

dispatcher = EventDispatcher()
on!(dispatcher, "MESSAGE_CREATE") do data
    println("Message received: ", data["content"])
end
source
Nobelium.Gateway.off! — Function
off!(dispatcher::EventDispatcher, event::String, handler::Function)

Remove an event handler for a specific event type.

Arguments

  • dispatcher: The event dispatcher
  • event: Event name
  • handler: Handler function to remove (must be the same function object)

Returns

  • true if handler was found and removed, false otherwise
source
Nobelium.Gateway.dispatch — Function
dispatch(dispatcher::EventDispatcher, event::String, data::Dict)

Dispatch an event to all registered handlers. Handlers are executed asynchronously in separate Tasks to prevent blocking. Exceptions in handlers are caught and logged, but do not affect other handlers.

Arguments

  • dispatcher: The event dispatcher
  • event: Event name
  • data: Event data dictionary

Notes

  • Each handler runs in its own Task via @async
  • Exceptions are isolated - one handler failing doesn't affect others
  • Handlers receive a copy of the data to prevent race conditions
source

Example Usage

Event Handling

using Nobelium.Gateway

dispatcher = EventDispatcher()

# Register a handler
on!(dispatcher, "MESSAGE_CREATE") do data
    println("Message: ", data["content"])
end

# Register multiple handlers for same event
on!(dispatcher, "MESSAGE_CREATE") do data
    println("Author: ", data["author"]["username"])
end

# Remove a handler
handler = data -> println(data)
on!(dispatcher, "GUILD_CREATE", handler)
off!(dispatcher, "GUILD_CREATE", handler)

Using Intents

using Nobelium.Gateway: Intents

# Combine intents
intents = Intents.GUILDS | Intents.GUILD_MESSAGES | Intents.MESSAGE_CONTENT

# Check for specific intent
Intents.has_intent(intents, Intents.GUILDS)  # true

# Check for privileged intents
Intents.is_privileged(intents)  # true (MESSAGE_CONTENT is privileged)

# List enabled intents
Intents.list_intents(intents)  # ["GUILDS", "GUILD_MESSAGES", "MESSAGE_CONTENT"]
