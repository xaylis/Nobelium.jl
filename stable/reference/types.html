Types ​

Discord's entities as Julia structs. Absent fields are missing, explicit nulls are nothing — see Optional and Nullable.

Nobelium.ApplicationRoleConnection Type
julia
ApplicationRoleConnection

The role-connection metadata a user has attached for an application.

source
Nobelium.Connection Type
julia
Connection

A linked third-party account (Steam, Twitch, ...) on a user's profile.

source
Nobelium.User Type
julia
User

A Discord user account. Bots see most fields only on themselves or via OAuth2; email and verified require the email scope.

source
Nobelium.display_name Method
julia
display_name(u::User) -> String

The name clients show for u: the global display name when set, otherwise the username.

source
Nobelium.mention Method
julia
mention(u::User) -> String

The mention string for u, e.g. "<@80351110224678912>".

source
Nobelium.Role Type
julia
Role

A guild role. color is deprecated in favor of colors.

source
Nobelium.RoleTags Type
julia
RoleTags

Metadata on managed roles. The null-typed fields (premium_subscriber, available_for_purchase, guild_connections) act as booleans: nothing when the tag applies, missing when it doesn't.

source
Nobelium.mention Method
julia
mention(r::Role) -> String

The mention string for r, e.g. "<@&41771983423143936>".

source
Nobelium.Emoji Type
julia
Emoji

A custom guild or application emoji. In reaction payloads for standard unicode emoji, id is null and name holds the unicode character.

source
Nobelium.Sticker Type
julia
Sticker

tags is a comma-separated list of autocomplete keywords for standard stickers, or the name of the associated emoji for guild stickers.

source
Nobelium.Guild Type
julia
Guild

A Discord server. owner and permissions only appear on partial guilds from get_current_user_guilds; the approximate counts require with_counts=true.

source
Nobelium.GuildPreview Type
julia
GuildPreview

A publicly previewable summary of a guild, from get_guild_preview.

source
Nobelium.GuildWidget Type
julia
GuildWidget

The public widget of a guild. Member fields are anonymized.

source
Nobelium.IncidentsData Type
julia
IncidentsData

Timestamps of a guild's security incident actions and detections.

source
Nobelium.Integration Type
julia
Integration

A guild integration (twitch, youtube, discord, or guild_subscription).

source
Nobelium.WelcomeScreen Type
julia
WelcomeScreen

The welcome screen of a Community guild, shown to new members.

source
Nobelium.GuildOnboarding Type
julia
GuildOnboarding

A guild's new-member onboarding configuration.

source
Nobelium.OnboardingPromptOption Type
julia
OnboardingPromptOption

An option in an onboarding prompt. When creating or updating one, set emoji_id/emoji_name/emoji_animated rather than emoji.

source
Nobelium.DiscordChannel Type
julia
DiscordChannel

A guild channel, DM, group DM, or thread. Which fields are set depends on type — threads carry thread_metadata, forum and media channels the default_* fields, and so on.

source
Nobelium.ForumTag Type
julia
ForumTag

A tag applicable to threads in a forum or media channel. At most one of emoji_id and emoji_name is set.

source
Nobelium.PermissionOverwrite Type
julia
PermissionOverwrite

A per-channel permission overwrite; type is 0 for a role, 1 for a member.

source
Nobelium.ThreadMember Type
julia
ThreadMember

A user's membership in a thread. id (the thread) and user_id are omitted on members inside GUILD_CREATE threads; member is only sent when requested with with_member.

source
Nobelium.mention Method
julia
mention(c::DiscordChannel) -> String

The mention string for c, e.g. "<#103735883630395392>".

source
Nobelium.VoiceState Type
julia
VoiceState

A user's voice connection status in a guild.

source
Nobelium.StageInstance Type
julia
StageInstance

A live Stage: the topic and settings of an ongoing event in a Stage channel.

source
Nobelium.GuildScheduledEventUser Type
julia
GuildScheduledEventUser

A user subscribed to a scheduled event, with their guild member when requested.

source
Nobelium.RecurrenceRule Type
julia
RecurrenceRule

How often a scheduled event recurs, a stricter subset of iCalendar RFC 5545. The end, by_year_day, and count fields cannot be set by clients.

source
Nobelium.RecurrenceRuleNWeekday Type
julia
RecurrenceRuleNWeekday

A weekday within a specific week (n = 1-5) for a recurrence rule.

source
Nobelium.GuildTemplate Type
julia
GuildTemplate

A shareable snapshot of a guild that new guilds can be created from. serialized_source_guild is a partial Guild with placeholder integer IDs.

source
Nobelium.ActivityLocation Type
julia
ActivityLocation

Where an activity instance is running: kind is "gc" for a guild channel or "pc" for a private channel.

source
Nobelium.Application Type
julia
Application

A Discord application. Many contexts (OAuth2, message metadata) carry partial applications with most fields absent.

source
Nobelium.ApplicationRoleConnectionMetadata Type
julia
ApplicationRoleConnectionMetadata

One metadata field an application exposes for role connections; key is what users' ApplicationRoleConnection records are matched against.

source
Nobelium.TeamMember Type
julia
TeamMember

A member of a Team. role is "admin", "developer", or "read_only"; the team owner is identified by Team.owner_user_id instead.

source
Nobelium.Webhook Type
julia
Webhook

A low-effort way to post messages to a channel. token is only returned for incoming webhooks, and user is absent when fetched with the webhook token.

source
Nobelium.Invite Type
julia
Invite

An invite to a guild or group DM channel. The metadata fields (uses, max_uses, max_age, temporary, created_at) are only present on invites fetched from a guild or channel's invite list.

source
Nobelium.InviteStageInstance Type
julia
InviteStageInstance

Stage details on an invite to a Stage channel. Deprecated by Discord.

source
Nobelium.Embed Type
julia
Embed

Rich content attached to a message. type is one of "rich", "image", "video", "gifv", "article", "link", or "poll_result" — always "rich" for embeds sent by bots and webhooks.

source
Nobelium.EmbedThumbnail Type
julia
EmbedThumbnail

An embed thumbnail; Discord documents it with the same structure as EmbedImage.

source
Nobelium.Component Type
julia
Component

Supertype of every message or modal component. Deserializes polymorphically from the numeric type field; an unrecognized type yields an UnknownComponent rather than throwing.

source
Nobelium.Container Type
julia
Container

A components-v2 layout component grouping other components behind an optional accent color, similar to an embed's side bar.

source
Nobelium.FileComponent Type
julia
FileComponent

A components-v2 attachment reference; Discord calls this component "File" on the wire (FileComponent avoids clashing with DiscordFile).

source
Nobelium.Label Type
julia
Label

A modal-only wrapper attaching a label and description to an interactive child component.

source
Nobelium.Section Type
julia
Section

A layout component (components-v2) grouping up to three TextDisplayComponent components with a Button or Thumbnail accessory.

source
Nobelium.UnknownComponent Type
julia
UnknownComponent

A component whose type this version of Nobelium doesn't recognize yet. raw holds the untouched payload so callers can still inspect it.

source
Nobelium.Poll Type
julia
Poll

A poll attached to a message. results is absent until Discord has tallied votes, which can lag slightly behind the raw vote count.

source
Nobelium.PollCreateRequest Type
julia
PollCreateRequest

The shape create_message and friends expect under a poll field, distinct from Poll in that answers carry no answer_id yet and duration replaces expiry.

source
Nobelium.AutoModerationActionMetadata Type
julia
AutoModerationActionMetadata

Action-specific configuration; which fields are relevant depends on the action's type.

source
Nobelium.AutoModerationRule Type
julia
AutoModerationRule

A rule that automatically takes actions when its trigger matches user content.

source
Nobelium.AutoModerationTriggerMetadata Type
julia
AutoModerationTriggerMetadata

Trigger-specific rule configuration; which fields are relevant depends on the rule's trigger type.

source
Nobelium.Entitlement Type
julia
Entitlement

A user's or guild's access to a SKU. starts_at/ends_at are absent on test entitlements and null on perpetual ones.

source
Nobelium.SKU Type
julia
SKU

A premium offering an application sells on Discord — a durable item, a consumable, or a subscription.

source
Nobelium.Subscription Type
julia
Subscription

A user's recurring purchase of one or more SKUs. country is only present when queried with a private OAuth scope.

source
Nobelium.SoundboardSound Type
julia
SoundboardSound

A custom sound that can be played in a guild's voice channels via the soundboard. sound_id doubles as the sound's own id.

source
Nobelium.Lobby Type
julia
Lobby

An ephemeral space, created via the Discord Social SDK, that a set of users can join and chat in. linked_channel is set when a guild channel has been linked for the lobby's messages to relay into.

source
Nobelium.LobbyMember Type
julia
LobbyMember

A user's membership in a Lobby, with arbitrary application-defined metadata.

source
Nobelium.AllowedMentions Type
julia
AllowedMentions

Controls which mentions in a message's content (or component content) actually notify users, independent of what the content contains. parse entries are "roles", "users", and/or "everyone".

source
Nobelium.Message Type
julia
Message

A message sent in a channel. content, embeds, attachments, components come back empty (and poll absent) unless the app has the MESSAGE_CONTENT privileged intent.

source
Nobelium.MessageInteractionMetadata Type
julia
MessageInteractionMetadata

Metadata about the interaction a message was sent in response to. Discord documents three variants (application command, message component, modal submit); this struct merges them; which fields are set depends on type.

source
Nobelium.MessageReference Type
julia
MessageReference

Points at another message: a reply (DEFAULT), a forward (FORWARD), or the source of a crosspost/pin/channel-follow message. channel_id is optional when creating a reply but required for forwards.

source
Nobelium.MessageSnapshot Type
julia
MessageSnapshot

A point-in-time copy of a forwarded message.

source
Nobelium.SnapshotMessage Type
julia
SnapshotMessage

The minimal subset of Message fields Discord includes in a MessageSnapshot: type, content, embeds, attachments, timestamp, edited_timestamp, flags, mentions, mention_roles, stickers, sticker_items, and components — notably no id or author.

source
Nobelium.ApplicationCommand Type
julia
ApplicationCommand

A slash, user, message, or entry-point command an application has registered globally or in a guild.

source
Nobelium.Interaction Type
julia
Interaction

A user's invocation of an application command, message component, or modal. member is set in guilds, user in DMs; data is absent only for pings.

source
Nobelium.InteractionCallbackResponse Type
julia
InteractionCallbackResponse

What create_interaction_response returns when called with with_response=true.

source
Nobelium.InteractionData Type
julia
InteractionData

The data payload of an Interaction. Discord documents a separate shape per interaction type; this struct merges them, so which fields are set depends on Interaction.type.

source
Nobelium.AuditLog Type
julia
AuditLog

A page of a guild's audit log, with the entries plus the objects they reference.

source
Nobelium.AuditLogChange Type
julia
AuditLogChange

One changed field on the entry's target. new_value/old_value mirror the type of the field named by key, so they are left untyped.

source
Nobelium.AuditLogEntryInfo Type
julia
AuditLogEntryInfo

Extra context for some audit log entries; which fields are set depends on action_type.

source
Nobelium.Activity Type
julia
Activity

A user's activity — playing a game, streaming, listening, a custom status, etc.

source
Nobelium.ActivityButton Type
julia
ActivityButton

A Rich Presence button. Discord sends buttons on the wire as an array of label strings; bots cannot see the URLs of other users' activity buttons.

source
Nobelium.ClientStatus Type
julia
ClientStatus

A user's platform-dependent status from a PresenceUpdate event. Active sessions carry "online", "idle", or "dnd"; offline platforms are absent.
